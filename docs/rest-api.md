# REST API reference

The API is served on `http://localhost:8000` by the `trovia` command (or by the Docker container,
see [install](install.md#docker)). Start it by running `trovia` in a terminal. Interactive
documentation (generated by FastAPI) is at <http://localhost:8000/docs>, and the machine-readable
schema is at <http://localhost:8000/openapi.json>. The port can be changed with
`trovia config set port 8001`.

There is no authentication. The service listens on `127.0.0.1` only, and it also refuses any
request whose `Host` header is not `localhost` or `127.0.0.1` (HTTP 400), which stops a web page
from reaching it through DNS rebinding. See `ALLOWED_HOSTS` in [configuration](configuration.md).

## Endpoints

| Method | Path | Purpose |
|---|---|---|
| `POST` | `/v1/search` | Run a search |
| `GET` | `/health` | Liveness check |

### `GET /health`

Returns `{"status": "ok"}` once the service has started and the reranker model is loaded.

```bash
curl http://localhost:8000/health
```

### `POST /v1/search`

Send a JSON body; receive a JSON response.

#### Request

| Field | Type | Default | Description |
|---|---|---|---|
| `query` | string | required | The question or search terms. Must not be empty. |
| `search_depth` | `"basic"` \| `"advanced"` | `"basic"` | `basic` reads `max_results` pages and returns 6 passages by default. `advanced` reads at least 8 pages and returns 12 passages by default. |
| `max_results` | integer, 1–10 | `5` | How many pages to read in `basic` depth. In `advanced` depth the number read is `max(max_results, 8)`. |
| `top_k_chunks` | integer, 1–50 | 6 (`basic`) / 12 (`advanced`); set your own default with `trovia config` | Maximum number of passages returned in total. |
| `max_chunks_to_rerank` | integer, 1–500 | 300 (`max_chunks_to_rerank` setting; 0 = all) | Maximum number of candidate passages sent to the reranker. Real `advanced` searches produce 150 to 220 candidates and scoring all of them takes about 0.3 s, so the default of 300 rarely applies. Lowering it makes results worse, not much faster (a cap of 100 lost 4 of the top 12 passages in testing); see [how-it-works](how-it-works.md#stage-4-reranking-troviarerankerpy) for how candidates are chosen. |
| `max_chunks_per_url` | integer, 1–50 | 2 (`max_chunks_per_url` setting) | Maximum number of passages returned from any single page. |
| `include_raw_markdown` | boolean | `false` | Also return the full extracted Markdown of each page that was read. |
| `bypass_cache` | boolean | `false` | Ignore the caches for this request and fetch everything fresh. The fresh result is stored. |

Only `query` is required. A `max_chunks_per_url` of 1 gives the most variety (one passage per
page); a higher value lets a very relevant page contribute more. The number of passages you
actually receive can be lower than `top_k_chunks` if there are not enough eligible passages
under the per-page limit.

#### Response

HTTP 200 with:

| Field | Type | Description |
|---|---|---|
| `query` | string | The query as received. |
| `search_provider_used` | string | `brave`, `serper`, `searxng`, `ddgs` (DuckDuckGo), or `none` if no provider returned results. |
| `latency_ms` | integer | Time taken to serve this request, including cache lookups. |
| `synthesized_context` | string | All returned passages as Markdown, each preceded by `## Source: <title> (<url>)` and separated by `---`. Ready to paste into a prompt. |
| `results` | array | The same passages as structured data (below), best first. |
| `raw_markdown` | object \| null | Map of URL → full page Markdown. Present only when `include_raw_markdown` is true; contains only pages that were actually read (not snippet-only ones). |
| `error` | string \| null | Set when the search could not be completed. `null` on success. |

Each item in `results`:

| Field | Type | Description |
|---|---|---|
| `title` | string | Title of the source page. |
| `url` | string | URL of the source page. |
| `chunk_content` | string | The passage text. |
| `relevance_score` | number | Reranker score, 0 to 1. Useful for ordering; with this model most good passages are close to 1.0, so do not treat it as an absolute measure. |
| `extraction_tier` | string | How the page was read: `tier1_trafilatura`, `tier2_jina`, or `snippet_only`. |
| `is_snippet` | boolean | `true` if the passage is the search engine's snippet rather than text from the page. |
| `cached` | boolean | `true` if this came from a cache. A full cached response marks every result `cached: true`. |

#### Example

```bash
curl -X POST http://localhost:8000/v1/search \
  -H "Content-Type: application/json" \
  -d '{
        "query": "rust tokio async mutex vs std sync mutex performance",
        "top_k_chunks": 4,
        "max_chunks_per_url": 1
      }'
```

Abbreviated response:

```json
{
  "query": "rust tokio async mutex vs std sync mutex performance",
  "search_provider_used": "brave",
  "latency_ms": 5102,
  "synthesized_context": "## Source: Shared state | Tokio (https://tokio.rs/tokio/tutorial/shared-state)\nGenerally, using a blocking mutex ...\n\n---\n\n## Source: ...",
  "results": [
    {
      "title": "Shared state | Tokio",
      "url": "https://tokio.rs/tokio/tutorial/shared-state",
      "chunk_content": "Generally, using a blocking mutex inside async code is fine ...",
      "relevance_score": 0.9992,
      "extraction_tier": "tier1_trafilatura",
      "is_snippet": false,
      "cached": false
    }
  ],
  "raw_markdown": null,
  "error": null
}
```

#### Errors

| Situation | Response |
|---|---|
| Invalid request (empty `query`, a value out of range, an unknown `search_depth`, malformed JSON) | HTTP **422** with a FastAPI validation body describing the offending field |
| No search provider returned results, or an unexpected failure | HTTP **200** with `results: []`, `synthesized_context: ""`, and `error` set to a message |
| A single page could not be read | Not an error. That page falls back to its snippet (`extraction_tier: "snippet_only"`). |

Because failures return HTTP 200, check `error` (or whether `results` is empty) rather than
only the status code.

## Client examples

### curl (Git Bash, macOS, Linux)

See the example above. Add `-H "Accept: application/json"` if you like; it is not required.

### PowerShell

```powershell
$body = @{
    query        = "python asyncio gather vs taskgroup"
    search_depth = "advanced"
    top_k_chunks = 8
} | ConvertTo-Json

$r = Invoke-RestMethod -Uri http://localhost:8000/v1/search -Method Post `
        -ContentType "application/json" -Body $body

$r.synthesized_context
```

### Python

```python
import httpx

resp = httpx.post(
    "http://localhost:8000/v1/search",
    json={"query": "python asyncio gather vs taskgroup", "max_chunks_per_url": 1},
    timeout=60,
)
resp.raise_for_status()
data = resp.json()

if data["error"]:
    print("search failed:", data["error"])
else:
    prompt_context = data["synthesized_context"]   # paste into your LLM prompt
    for r in data["results"]:
        print(r["relevance_score"], r["url"])
```

Use a generous client timeout (30–60 s): an uncached search commonly takes 4–11 seconds.

## Choosing options

| You want | Use |
|---|---|
| The quickest reasonable answer | defaults (`basic`) |
| More coverage for a hard or broad question | `"search_depth": "advanced"` |
| Short context for a small prompt budget | lower `top_k_chunks` (for example 3) |
| Many different sources rather than deep dives into one | `"max_chunks_per_url": 1` |
| One very relevant page in depth | raise `max_chunks_per_url` (for example 5) |
| Fresh results for something that just changed | `"bypass_cache": true` |
| The full text of the pages, not only the best passages | `"include_raw_markdown": true` |
